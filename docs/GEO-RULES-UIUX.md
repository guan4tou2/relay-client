## 1. 這個功能在做什麼

現在的分流只認**程式**（`chrome.exe` → 路由 1）。這次要加的是認**目的地**，而且能和程式條件組合：

| 規則種類 | 例子 | 底層對應 |
|---|---|---|
| 網域（完全相符） | `example.com` | `domain` |
| 網域後綴 | `*.google.com` | `domain_suffix` |
| 網域關鍵字 | `tracker` | `domain_keyword` |
| 網域正規表示式 | `^ad\d+\.example\.com$` | `domain_regex` |
| IP / 網段 | `10.0.0.0/8`、`8.8.8.8` | `ip_cidr` |
| **地區 / 分類（規則庫）** | 台灣 IP、中國網站、廣告網域 | `rule_set`（`.srs`） |

還有 **埠**（`443`、`8000-9000`）與 **協定**（`tcp` / `udp`）兩種條件。
每條規則的走向可以是 **直連 / 某條路由 / 封鎖**（封鎖是新的，之前只有直連與路由）。

**設計上最重要的一件事**：使用者腦中的問題只有一個——「**我開這個網站，會走哪一條？**」
所有畫面都要服務這個問題：規則清單要看得出順序與勝負，模擬器要能當場驗證。

### 一定要讓使用者看懂的三件事

1. **順序決定勝負**：由上往下第一條命中的規則就贏，後面的不再比對。清單必須看得出「上面優先」。
2. **一條規則裡的條件是 AND**：`chrome.exe` **且** `*.netflix.com` **且** `443` 才算命中。
   規則列與編輯面板都要讓「而且」這件事一眼看懂，不能讓人誤以為是「或」。
3. **地區規則需要先下載規則庫**：沒下載的規則庫，**整條規則會被引擎略過**（不是只忽略那個條件——
   否則「Chrome 連台灣 IP」會放寬成「Chrome 全部流量」）。這種「規則存在但沒作用」的狀態必須有明確視覺。

## 3. 資訊架構

```
分流（既有分頁，全寬版面）
├── 引擎卡片（既有：電源鈕、狀態、TUN 名稱、規則外流量走向、UDP 開關）
│   └── ＋ 規則模擬器一列（新增）
├── 子導覽：〔規則〕〔規則庫〕
├── 規則    → 單一規則表（一列一條規則，條件用 chip 呈現）
└── 規則庫  → 規則庫管理（目錄 / 已安裝 / 匯入）
右側欄：攔截中的程式 + 引擎健康（既有，維持）
```

「規則庫」放在同一層的第二個子分頁，不要藏進設定裡——它是使用者建地區規則時的必經步驟。

## 4. 資料模型（設計時會用到的欄位）

```jsonc
// 一條規則（schema 2）。when 裡每個條件都可省略，有幾個就要「同時成立」幾個（AND）。
{
  "id": "r1",
  "name": "Chrome 看 Netflix 走日本",   // 顯示名稱，使用者自取
  "on": true,
  "target": "r-jp",                    // "direct" | "block" | <routeId>
  "when": {
    "app":     { "match": "name",   "value": "chrome.exe" },   // name | path
    "dest":    { "match": "suffix", "value": "netflix.com" },  // domain|suffix|keyword|regex|ip|ruleset
    "port":    "443, 8000-9000",
    "network": "tcp"                                           // tcp | udp（省略 = 兩者皆可）
  }
}
// 所有 value 都接受「換行 / 逗號 / 分號分隔的字串」或字串陣列

// 一個已安裝的規則庫
{
  "tag": "geoip-tw", "kind": "geoip", "label": "台灣 IP",
  "bytes": 184320, "updatedAt": 1757500000000,
  "source": "catalog",             // catalog（從目錄下載） | import（使用者匯入）
  "missing": false                 // true = 檔案被刪掉，規則會被略過
}
```

**內建規則庫目錄**（後端已寫好，設計時就照這份畫）：

- 地區（GeoIP）：台灣、中國、日本、香港、韓國、新加坡、美國、私有/內網
- 分類（GeoSite）：中國網站、非中國網站、Google、GitHub、OpenAI、Netflix、YouTube、Telegram、X/Twitter、Apple、Microsoft、Steam、廣告/追蹤器

## 5. 逐畫面規格

### 5.1 (A) 子導覽

- 位置：引擎卡片下方、規則表上方，靠左。
- 形式：沿用既有的分段控制（`segCss`）——`padding:2px`、`background:var(--fill2)`、`border-radius:9px`，選中項為 `var(--card)` + 陰影。
- 兩個項目：`規則`、`規則庫`，各自帶數量 badge（`規則 12`、`規則庫 3`）。數量為 0 時不顯示 badge。
- 標題列的「新增」按鈕文案跟著切換：`新增規則` / `下載規則庫`。

### 5.2 (B) 規則清單（單一表）

沿用程式規則表的骨架（`var(--card)` 卡片、`1px solid var(--sep)` 分隔線、10px 直向 padding、可拖曳排序）。

**欄位**

| 欄 | 寬 | 內容 |
|---|---|---|
| 拖曳把手 | 26px | 六點圖示，`var(--text3)` |
| 序號 | 28px | `1` `2` `3`…（等寬字），強調「順序＝優先權」 |
| 規則 | 244px | 上：`name`（600 字重）／下：**條件摘要**（等寬字、`var(--text3)`、超過截斷） |
| 條件 | 132px | 每個條件一個 chip：`程式` `完整路徑` `後綴` `IP` `地區/分類` `埠` `TCP`… |
| 流量走向 | 彈性 | 圓點 + 走向名稱（`直接連線` / 路由名 / `封鎖`） |
| 命中次數 | 96px | 引擎執行中才有值，否則 `—`（等寬字、靠右） |
| 操作 | 96px | 啟用開關（40×24 pill）、編輯、刪除（二次確認） |

**條件摘要的寫法**（一列要塞得下「而且」的語意）
- 條件之間用 `·` 分隔，例：`chrome.exe · 後綴 netflix.com · 埠 443 · TCP`
- 單一條件多值：`netflix.com、hulu.com +3`（前兩個 + 剩餘數量），完整清單放 `title` tooltip
- 地區/分類：顯示規則庫的中文名 + 代號，例：`台灣 IP · geoip-tw`
- 沒有任何條件的規則（不會生效）：灰字 `（沒有任何條件，不會生效）`

> **設計上最需要解掉的問題：要讓人一眼看出這些條件是「而且」不是「或」。**
> 建議 chip 之間放淡色的 `＋`，或在條件欄下方加一行極小的 `全部符合才命中`——兩種都出稿讓我們挑。

**列的狀態**

| 狀態 | 視覺 |
|---|---|
| 啟用中、引擎執行中、走代理 | 圓點 `var(--good)` + `dotBeat` 呼吸動畫 |
| 啟用中、引擎未執行 | 圓點 `var(--text3)`，其餘正常 |
| 停用 | 整列底色 `var(--fill2)`、文字降到 `var(--text3)` |
| 走向＝封鎖 | 圓點與走向文字用 `var(--red)`，走向徽章 `封鎖` 為紅底淡色 |
| **規則庫未下載**（規則存在但引擎會略過） | 整列左緣 3px `var(--amber)` 標記；種類徽章換成 `⚠ 需下載`；列尾多一顆 `下載` 主按鈕 |
| 規則庫檔案遺失（`missing`） | 同上，文案改成 `⚠ 檔案遺失`，按鈕 `重新下載` |

**表尾固定列**：沿用既有的「其他所有流量」列（灰底、`預設` 徽章、右側「變更」按鈕），文案由「其他所有程式」改為 **「其他所有流量」**——因為現在預設走向同時管程式與網域。

**篩選列**（表頭上方，靠右）：`全部` / `走代理` / `直連` / `封鎖`，沿用既有 `splitFilter` 的分段控制。左側再放一個搜尋框 `搜尋網域或規則名稱…`。

### 5.3 順序（取代原本的「比對順序」開關）

單一規則表之後不再需要任何順序開關——**表的順序就是優先權**。要強化的是「拖曳可改順序」：

- 序號欄（28px）用等寬字；拖曳後重新編號並閃一下 `var(--accent-dim)`。
- 拖曳中該列 `opacity:.5`，目標位置顯示 2px `var(--accent)` 插入線。
- 表頭上方一行灰字：`由上往下比對，第一條符合的規則決定走向。`

### 5.4 (C) 規則編輯面板（可組合條件）

右側滑入 sheet，寬 470px，沿用既有 `sheetIn` 動畫與 sheet 骨架（標題列 / 可捲動 body / 底部動作列）。

**標題**：`新增規則` / `編輯規則`

**Body 由上而下**

1. **條件區**——這是這次改版的核心。四種條件各是一張可折疊的卡片，預設全部收合成一列，
   點「＋ 加入條件」才展開。已加入的條件卡片右上角有 `✕` 移除。

   | 條件 | 收合時顯示 | 展開後 |
   |---|---|---|
   | 程式 | `程式：chrome.exe` | 分段控制 `程式名稱` / `完整路徑` + 既有的三種挑選方式（執行中的程式 / 瀏覽檔案 / 手動輸入） |
   | 目的地 | `後綴：netflix.com` | 種類分段控制（見下）+ 值輸入區 |
   | 埠 | `埠：443, 8000-9000` | 單行輸入，說明 `可寫單一埠、逗號分隔多個，或 8000-9000 範圍` |
   | 協定 | `協定：TCP` | 三段控制 `不限` / `TCP` / `UDP` |

   卡片之間顯示一個置中的淡色 `＋ 而且`（`var(--text3)`，11px），把 AND 語意講死。
   一個條件都沒加時，底部動作列的「儲存規則」為 disabled，並提示 `至少要有一個條件`。

2. **目的地條件的種類**（分段控制，兩排三格）
   `網域` `後綴` `關鍵字` `正則` `IP / 網段` `地區 · 分類`
   每次切換，下面的輸入區與說明文字跟著換。

3. **值的輸入區**（依種類變形）

   | 種類 | 輸入元件 | placeholder | 底下說明 |
   |---|---|---|---|
   | 網域 | 多行 textarea（自動長高，最少 3 行） | `example.com` | `完全相符才命中，一行一個。` |
   | 後綴 | 同上 | `*.google.com` | `含所有子網域。開頭的 *. 可寫可不寫。` |
   | 關鍵字 | 同上 | `doubleclick` | `網域中只要含這段文字就命中，最寬鬆，容易誤傷。` |
   | 正則 | 單行等寬輸入 | `^ad\d+\.example\.com$` | `RE2 語法。寫錯只會不命中，不會讓引擎壞掉。` |
   | IP / 網段 | 多行 textarea | `10.0.0.0/8` | `可寫單一 IP（自動視為 /32）或 CIDR 網段。` |
   | 地區 · 分類 | **規則庫挑選器**（見下） | — | `依目的地所屬國家/地區或網站分類比對，需要先下載規則庫。` |

   多行輸入的右下角顯示即時計數：`已輸入 4 個網域`。

4. **規則庫挑選器**（`地區 · 分類` 專用）
   - 一顆下拉按鈕，展開為可搜尋清單，分兩組：**已安裝**（可直接選）與 **目錄中**（選了會問要不要下載）。
   - 每一項：左側 kind 圖示（🌏 地區 / 🏷 分類，用線性 SVG 不用 emoji）、中文名、右側代號等寬小字與檔案大小。
   - 未安裝的項目右側顯示 `未下載` 灰徽章；點選後 sheet 內就地顯示一條 inline 提示：`此規則庫尚未下載，儲存後規則不會生效。〔立即下載〕`
   - 支援複選（一條規則可涵蓋多個規則庫，例如「日韓 IP」= geoip-jp + geoip-kr），已選的以 chip 形式列在按鈕下方，chip 可單獨移除。

5. **顯示名稱**：單行輸入，`例如 Chrome 看 Netflix 走日本`。留空時自動用條件摘要當名稱。

6. **流量走向**：下拉按鈕，選項為 `直接連線（不經代理）` / 各條路由 / **`封鎖（丟棄連線）`**。
   - 封鎖選項在清單中以 `var(--red)` 圓點與紅色文字呈現，並附說明 `連線直接丟棄，適合廣告與追蹤網域。`
   - 若選的路由其上游不支援 UDP 且 UDP 轉發開啟 → 沿用既有的琥珀色警告樣式。

7. **對應 config.json 預覽**：沿用既有的灰底等寬區塊，即時反映草稿（含完整的 `when` 物件）。

**底部動作列**：左側說明 `儲存後立即生效，無需重啟引擎`，右側 `取消` / `儲存規則`。

**驗證與錯誤**（就地顯示在對應欄位下方，紅字 11px）
- 值全空 → `請至少輸入一個值`
- 正則語法錯 → `正規表示式語法錯誤：<訊息>`
- IP 格式錯 → `第 2 行不是合法的 IP 或網段`
- 種類為地區但沒選規則庫 → `請選擇至少一個規則庫`
- 一個條件都沒加 → `至少要有一個條件`（儲存鈕 disabled）
- 埠格式錯 → `埠只能是數字或 8000-9000 這種範圍`

> **實作狀態（已完成）**：分流分頁已依 `SOCKS5 Client v8 · 分流單一規則表` 實作完成——
> 單一規則表、內建「本機與內網」列、模式三段（規則／全域／直連）、可折疊條件編輯面板、
> 規則庫挑選與下載、規則模擬器、空狀態與篩選列全部接上真實 IPC。

### 5.5 (D) 規則庫管理

子分頁「規則庫」的全寬版面，兩個區塊。

**上：已安裝（卡片列表，每列一個規則庫）**

| 元素 | 內容 |
|---|---|
| 左 | kind 圖示（地區 / 分類）+ 中文名 |
| 中 | 代號（等寬）、檔案大小、`更新於 3 天前`、來源徽章（`目錄` / `手動匯入`） |
| 右 | `更新`（手動匯入者為 disabled + tooltip `手動匯入的規則庫沒有更新來源`）、`移除`（二次確認） |
| 被引用時 | 名稱右側顯示 `2 條規則使用中` 的小字；移除時的二次確認要改成警示文案 |
| `missing` | 整列琥珀色左緣 + `檔案遺失`，右側只留 `重新下載` |

區塊標題右側：`全部更新` 主按鈕 + `匯入 .srs / .json` 次按鈕。標題下一行小字：
`規則庫存在 %USERPROFILE%\AppData\Roaming\RelayClient\rulesets\，只有你按下載時才會連網。`

**下：目錄（可下載的內建清單）**

- 兩段分組：`地區（GeoIP）` 與 `網站分類（GeoSite）`，每組用 grid 卡片（每張 220–260px 寬）。
- 卡片：中文名（600 字重）、一行說明（`目的地 IP 屬於台灣`）、代號等寬小字、右下角 `下載` 按鈕。
- 已安裝的卡片：按鈕變成 `已安裝` 的 disabled 狀態 + 打勾圖示，卡片整體降飽和。
- 搜尋框：`搜尋規則庫…`，即時過濾兩組。

**下載中狀態**：按鈕就地變成細進度條（不用 modal），文案 `下載中… 1.2 MB`。失敗時卡片下方紅字 `下載失敗：<原因>`，按鈕變 `重試`。

**下載出口提示**：若設定裡指定了下載繞道路由，區塊頂端顯示一條中性通知條：
`規則庫下載將經由路由「日本節點」。`

### 5.6 (E) 規則模擬器

放在引擎卡片底部，跨整張卡片寬度的一列（引擎未執行時同樣可用——模擬器不需要 TUN）。

```
┌───────────────────────────────────────────────────────────────────┐
│ 🔍 [ 輸入網址、網域或 IP，例如 www.netflix.com          ] [測試]   │
│    可選：只測某支程式 [ chrome.exe ▾ ]                             │
└───────────────────────────────────────────────────────────────────┘
```

**結果**以卡片內展開的方式顯示（不要跳 modal）：

```
www.netflix.com  →  命中第 3 條「串流服務走日本節點」（網域後綴 *.netflix.com）
                    走向：日本節點 · SOCKS5 · 127.0.0.1:10812
```

- 命中規則的那一列，在下方規則表中同步高亮（`var(--accent-dim)` 底色，2 秒後淡出），並自動捲到可視範圍。這是整個功能最重要的「說服力」互動。
- 沒命中任何規則：`未命中任何規則 → 依預設走向：直接連線`。
- 命中的是被封鎖的規則：走向文字用紅色，補一句 `這個連線會被丟棄`。
- 命中的規則引用了未下載的規則庫：琥珀色提示 `此規則目前不會生效（規則庫未下載）`，並附 `下載` 按鈕。

### 5.7 (G) 設定頁新增區塊

在設定頁既有的列樣式下新增「**規則庫**」分組：

| 設定列 | 型態 | 預設 | 副標 |
|---|---|---|---|
| 自動更新規則庫 | 開關 | 關 | `開啟後會定期連網下載最新的地區與分類資料。關閉時本程式完全不連外。` |
| 更新頻率 | 下拉（每 1 / 3 / 7 / 30 天） | 每 7 天 | 只在自動更新開啟時可用 |
| 下載時經由 | 下拉（直連 / 各條路由） | 直連 | `GitHub 連不上時，可讓規則庫改走某條代理下載。` |
| 上次檢查 | 純文字 + `立即檢查` 按鈕 | `尚未檢查` | — |

### 5.8 (H) 空狀態與首次使用

**網域規則表為空時**（置中，沿用既有空狀態排版）：

> **還沒有網域規則**
> 依網域或地區決定走哪條路，例如「台灣網站直連、其他走代理」。
> 〔新增網域規則〕 〔套用常用範本〕

**「套用常用範本」** 展開為三個一鍵套用的卡片（這是降低上手成本的關鍵設計）：

| 範本 | 內容 | 需要的規則庫 |
|---|---|---|
| 台灣直連、其餘走代理 | `geoip-tw → 直連`、`geoip-private → 直連`，預設走向改為某條路由 | geoip-tw、geoip-private |
| 只有特定網站走代理 | 空的後綴規則 + 引導使用者填 | 無 |
| 擋掉廣告與追蹤 | `geosite-category-ads-all → 封鎖` | geosite-category-ads-all |

套用時若缺規則庫，先跳一個確認：`此範本需要下載 2 個規則庫（約 1.4 MB），要現在下載嗎？`

### 5.9 (I/J) 通知條與狀態

沿用既有 `renderSplitNotice()` 的通知條樣式（圓角、淡色底、左圖示、右動作連結）。新增的情境：

| 情境 | 色 | 文案 | 動作 |
|---|---|---|---|
| 有規則引用未下載的規則庫 | 琥珀 | `有 2 條規則引用尚未下載的規則庫，這些規則目前不會生效。` | `前往規則庫` |
| 規則庫超過 30 天未更新 | 中性 | `規則庫已 45 天未更新，地區判斷可能不準。` | `立即更新` |
| 網域規則存在但引擎未執行 | 中性 | `網域規則要在分流引擎執行時才會生效。` | `啟動引擎` |
| 只有 IP/地區規則、沒有網域規則 | 中性（可省） | `目前規則只看 IP，不需要嗅探網域，效能最好。` | — |
| 使用了關鍵字規則 | 琥珀 | `關鍵字規則比對範圍很寬，可能誤傷其他網站。` | — |

**「封鎖」的視覺語彙**（新的第三種走向，要一眼分辨）：圓點與文字 `var(--red)`，徽章底 `rgba(217,83,74,.14)`、字 `var(--red)`，圖示用禁止符號（圓圈加斜線）。

## 6. 關鍵互動與狀態機

**規則生效的完整流程**（設計時每一步都要有對應回饋）

```
建立規則 ──▶ 引擎執行中？ ──否──▶ 通知條：啟動引擎
                │是
                ▼
        引用規則庫？ ──是──▶ 已下載？ ──否──▶ 列內琥珀警示 + 下載按鈕
                │否                  │是
                └──────────┬─────────┘
                           ▼
                    立即生效（引擎背景重載，不需要使用者按套用）
```

- 任何規則變更都是**立即生效**：儲存後引擎在背景重啟並重載設定，過程約 1–2 秒。
  設計上用標題列的狀態文字短暫變成 `套用規則中…`（琥珀）再回到 `分流引擎執行中`，不要跳 modal、不要 disable 整頁。
- 拖曳排序：拖曳中該列 `opacity:.5`、目標位置顯示 2px `var(--accent)` 插入線，放開後序號欄重新編號並閃一下。
- 刪除：沿用既有的「再按一次確認」（按鈕變紅底打勾，2.5 秒後還原），不要用確認 modal。

## 8. 邊界情況清單（每一項都要有稿或至少有狀態註記）

1. 規則庫下載失敗（無網路 / GitHub 被擋 / 磁碟寫入失敗）
2. 規則庫檔案被使用者手動刪除 → `missing`
3. 規則指向已被刪除的路由 → 走向顯示「（路由已刪除）」，列以紅字標記
4. 同時有 200+ 條規則 → 清單需虛擬捲動或分頁的視覺提示
5. 單條規則含 500 個網域 → 摘要與 tooltip 的截斷策略
6. 正則寫錯 → 儲存時就地報錯，不讓它進到引擎
7. 引擎未提權 → 網域規則可以建立與模擬，但通知條要說明「尚未生效」
8. 斷線保護（kill-switch）觸發時 → 網域規則中原本走代理的也會被封鎖，狀態畫面要提到這件事
9. UDP 轉發開啟但上游不支援 → 沿用既有琥珀警告
10. 深色 / 淺色主題，兩套都要出稿

## 9. 設計代幣與元件複用（務必沿用）

顏色一律用 CSS 變數，不要寫死色碼：

```
--bg --panel --card --fill --fill2 --sep
--text --text2 --text3
--accent（藍，主要動作）--accent-dim（淡藍底）
--good（綠，運作中）--amber（琥珀，警告）--red（紅，封鎖 / 危險）--purple
```

- 字體：`Noto Sans TC` / `Microsoft JhengHei`；等寬（代號、IP、路徑、數值）：`JetBrains Mono` / `Cascadia Mono` / `Consolas`。
- 圓角：卡片 16px、sheet 內元件 9–12px、徽章 5–6px、pill 開關 12px。
- 既有可直接複用的元件：分段控制、40×24 pill 開關、右側 sheet、下拉選單、通知條、二次確認刪除按鈕、`dotBeat` 呼吸圓點、`fadeUp` / `sheetIn` 動畫。
- 全部離線：**不得引用任何遠端字型、圖片或 CDN**（app 有嚴格 CSP）。圖示一律內嵌線性 SVG，`stroke-width` 用 1.9–2。

## 10. 無障礙

- 子導覽用 `role="tablist"` / `role="tab"` / `aria-selected`，與既有分頁一致。
- 每個開關要有 `aria-label`（`啟用規則：串流服務走日本節點`）。
- 顏色不是唯一資訊：封鎖除了紅色還要有 `封鎖` 文字徽章；未下載除了琥珀色還要有 `未下載` 字樣。
- 鍵盤：`Ctrl+N` 新增規則（依目前子分頁決定型別）、`Esc` 關閉 sheet、模擬器輸入框 `Enter` 送出。
